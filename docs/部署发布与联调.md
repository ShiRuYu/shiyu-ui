# ShiYu UI 部署、发布与联调

## 开发环境

要求 Node.js `^22.18.0 || ^24.12.0`、pnpm 11+。后端默认运行在 9000，前端默认运行在 5888。

```powershell
pnpm install
pnpm run dev:naive
```

`apps/web-naive/.env.development` 设置 `VITE_GLOB_API_URL=/api`；Vite 将 `/api/*` 原样代理到 `VITE_PROXY_TARGET`（默认 `http://localhost:9000`）。因此浏览器和后端都使用 `/api/iam/auth/login` 等领域路径。

切换联调后端：

```powershell
$env:VITE_PROXY_TARGET='http://127.0.0.1:19014'
pnpm run dev:naive
```

## 发布门禁

```powershell
pnpm exec oxlint apps/web-naive/src
pnpm exec oxfmt --check apps/web-naive/src
pnpm run check:type
pnpm run test:unit
pnpm run test:contract
pnpm run build:naive
```

页面路由或后端菜单变更后先执行 `python scripts/docs/generate-page-route-reference.py`；脚本会逐条验证所有页面菜单对应的 Vue 组件。

接口变更流程：先启动目标后端，再执行 `pnpm run test:contract:update` 更新 `tests/contracts/shiyu-ai-openapi.json`；审查 OpenAPI diff 后执行 `pnpm run test:contract`。脚本会校验方法、动态路径、统一响应和 SSE 端点，不能用“只编译通过”代替契约审查。

## 生产部署

生产构建默认仍使用同源 `/api`：

```powershell
pnpm run build:naive
```

产物位于 `apps/web-naive/dist`，并生成 `dist.zip`。将静态文件部署到 Nginx/CDN，同时把同域 `/api/` 原样反向代理到后端。SPA 使用 hash 路由，静态托管无需为每个业务路由配置回退；若切换 history 模式，需要所有未知路径回退到 `index.html`。

Nginx 示例：

```nginx
location / {
    root /srv/shiyu-ui;
    try_files $uri $uri/ /index.html;
}

location /api/ {
    proxy_pass http://127.0.0.1:9000/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
    proxy_buffering off;
}
```

前后端分域部署时，构建前覆盖 `VITE_GLOB_API_URL` 为 HTTPS 后端地址，并在后端 `shiyu.web.cors.allowed-origin-patterns` 中只加入确切前端来源。不要使用 `*` 搭配凭证。

## 联调冒烟清单

1. 登录成功，用户、租户、角色完整。
2. 权限码和动态菜单加载成功；普通用户看不到管理区。
3. Agent 列表、编辑保存、流式对话正常。
4. 知识空间、上传/任务、检索和图谱正常。
5. 教育课程、练习、复习和 AI 对话正常。
6. `/api/iam/auth/refresh` 用 `accessToken` 轮换后新 token 可用、旧 token 401。
7. 无权限按钮返回 403，跨租户对象无法访问。
8. 文件上传、下载、删除符合租户与权限约束。
9. 直接刷新页面、移动端布局和错误页正常。

## 回滚

静态站点采用版本目录或不可变制品发布。保留上一版 `dist.zip`，验证新版本后再切换软链接/流量；出现问题直接回切上一制品。若回滚涉及 API 契约变化，必须同步回滚兼容的后端，不能只回滚前端。
