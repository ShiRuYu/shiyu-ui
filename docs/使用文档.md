# ShiYu UI 前端使用文档

> 面向终端用户、前端开发、联调测试和静态部署。命令默认在 `shiyu-ui` 根目录执行。

## 1. 环境准备

- Node.js 22.18+ 或 24.12+。
- pnpm 11+。
- 已启动的 `shiyu-ai`，本地默认 `http://127.0.0.1:9000`。
- 页面布局、选择器完整文本、Conversation/Runtime/MAGMA 边界见 [开发规范与对话决策](开发规范与对话决策.md)。

检查版本：

```powershell
node --version
pnpm --version
```

## 2. 安装和启动

```powershell
pnpm install --frozen-lockfile
pnpm -F @vben/web-naive run dev
```

浏览器访问 `http://127.0.0.1:5888`。

后端不在默认地址时：

```powershell
$env:VITE_PROXY_TARGET='http://127.0.0.1:9001'
pnpm -F @vben/web-naive run dev
```

环境变量要在启动 Vite 前设置。开发请求统一访问 `/api`，Vite 将原样转发该领域路径到后端。

## 3. 登录和工作上下文

1. 打开登录页，输入管理员或已分配角色的用户账号。
2. 登录成功后，系统加载用户信息、租户、权限码和菜单。
3. 若账号有多个租户或角色，可在界面中切换当前上下文。
4. 切换后页面菜单和按钮权限会重新生成。

本地 H2 种子数据包含用户名 `admin`，但密码由部署方管理，仓库不提供明文默认密码。请使用实际环境的管理员密码。

如果出现“菜单加载失败”：

- 点击页面重试。
- 确认后端 `/api/iam/menus/all` 可用。
- 清理旧站点缓存后重新登录。
- 让管理员检查菜单 `name` 是否重复、`component` 是否对应真实前端页面。

## 4. 功能使用

### 4.1 Agent 平台

推荐操作顺序：

1. 平台管理：新增 OpenAI、DeepSeek、Ollama 或其他兼容平台，配置地址和密钥。
2. 模型管理：新增该平台下的模型，并用调试对话验证。
3. Agent 管理：创建 Agent，填写名称、编码和基础配置。
4. 版本管理：创建版本或复制已有版本。
5. 流程编排：从节点面板添加节点，连接执行顺序，在属性表单中配置模型、提示词、工具、知识和路由条件。
6. 校验：保存并运行图校验，处理断连、缺少入口或无效配置。
7. 发布：发布并激活目标版本，启用/注册 Agent。
8. 调试：在聊天页观察流式输出和错误信息。

切换模型平台后，只能选择该平台可用模型。流式响应卡住时，先检查后端模型能力和代理是否缓存响应。

### 4.2 AI 工作区（Chat / Agent / RAG）

1. Chat 使用 `/workspace/chat`，保存原始 Conversation；编辑会创建新消息节点，重试会创建候选分支，停止生成会调用后端取消。
2. Agent 使用 `/workspace/agent`，先选择已发布 App/Version；Draft 版本只可预览或测试，不能直接执行。
3. RAG 使用 `/workspace/rag`，上下文片段必须显示来源、权限范围、引用和关系路径。
4. 平台、模型、App、版本和知识空间等下拉选项会按内容展开；名称过长时将鼠标悬浮在选中值上查看完整文本。
5. 断线后使用运行事件序号恢复，不要重复点击发送；运行轨迹和工具审批在右侧 Context/Trace 面板查看。

### 4.3 知识引擎

1. 创建或选择知识空间。
2. 在文档中心上传资料，等待解析任务完成。
3. 在知识资产查看生成的知识点，按需编辑关系。
4. 在图谱工作室检查结构。
5. 在索引/运维页面构建或重建索引。
6. 在检索实验室输入查询，比较检索结果。
7. 在评测中心建立样本，验证召回质量。
8. 将空间绑定到 Agent 的 RAG 节点。

文档上传成功但搜不到内容时，重点查看任务状态、索引版本、空间选择以及后端 Embedding 配置。

### 4.4 教育空间

- 学习：浏览课程、知识点、学习计划和资源。
- 练习与考试：答题、参加考试、查看结果和错题。
- 复习：查看今日复习和历史记录。
- AI 辅学：使用家教对话、规划、练习和报告生成。
- 学习分析：查看能力雷达、趋势、薄弱点和报告。
- 教育配置：维护学科、教材、章节、课程、题目、考试、学生、计划、资源和复习数据。

菜单和操作按钮取决于当前角色权限。看不到页面时先确认当前租户和角色，不建议通过前端改数据绕过权限。

### 4.6 系统管理

典型授权流程：

1. 创建租户或选择现有租户。
2. 创建角色。
3. 给角色分配菜单和权限码。
4. 创建用户或编辑用户的租户/角色分配。
5. 用户重新登录验证权限。

菜单管理中的组件标识不是任意 URL，必须使用 `feature:<domain>.<page>` 语义键（或系统布局标识）。普通管理员不应随意修改系统核心菜单。

## 5. 本地开发

### 5.1 常用命令

```powershell
# 启动 ShiYu 主应用
pnpm dev:naive

# 类型检查
pnpm -F @vben/web-naive run typecheck

# 应用单测
pnpm exec vitest run apps/web-naive/src

# 生产构建
pnpm -F @vben/web-naive run build

# 预览构建产物
pnpm -F @vben/web-naive run preview
```

只开发 ShiYu 时优先使用带 `@vben/web-naive` 过滤器的命令，避免无意构建整个 Vben workspace。

### 5.2 新增一个业务页面

1. 在对应 `features/<domain>` 下按 `api/model/composables/ui/pages/index.ts` 结构创建页面和组件。
2. 在 `features/<domain>/api` 增加接口和类型，并从 feature 公共入口导出。
3. 添加 `zh-CN`、`en-US` 文案。
4. 后端新增对应菜单、组件路径和权限码。
5. 为角色授权后重新登录。
6. 运行类型检查、应用单测和构建。
7. 对关键路径补充 Playwright。

### 5.3 调试请求

浏览器 Network 中应看到：

```text
/api/iam/auth/login
/api/iam/users/detail
/api/iam/auth/codes
/api/iam/menus/all
```

后端日志中对应：

```text
/api/iam/auth/login
/api/iam/users/detail
/api/iam/auth/codes
/api/iam/menus/all
```

若浏览器直接请求 `:9000/api/...` 并返回 404，请检查后端领域路由、端口和认证配置。

## 6. E2E 测试

先启动后端和前端，再设置测试密码：

```powershell
$env:E2E_USERNAME='admin'
$env:E2E_PASSWORD='<your-password>'
$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:5888'
pnpm run test:e2e
```

未设置 `E2E_PASSWORD` 时，认证类 smoke 用例会跳过。测试串行执行，因为默认管理员是单会话账号。

失败产物：

- HTML 报告：`playwright-report/`。
- 截图、trace 和其他结果：`test-results/`。

这些属于本地测试产物，不应作为业务源码修改提交。

## 7. 生产构建和部署

构建：

```powershell
pnpm -F @vben/web-naive run typecheck
pnpm exec vitest run apps/web-naive/src
pnpm -F @vben/web-naive run build
```

产物在 `apps/web-naive/dist`。发布服务器需要：

1. 托管该目录内的静态文件。
2. 将 `/api/**` 原样反向代理到 `shiyu-ai`，保留 `/api` 前缀。
3. 透传 `Authorization`、语言和 `version` 等请求头。
4. 对 SSE 关闭代理缓冲，延长读取超时。
5. 若后续接入后端 `/ws/usage`，再增加 WebSocket upgrade 与浏览器握手认证配置；当前用量页面使用 REST 查询，未消费该 WebSocket。
6. 使用 HTTPS，并按组织策略添加 CSP、HSTS 等安全响应头。

Nginx 语义示例：

```nginx
location /api/ {
    proxy_pass http://shiyu_backend/;
    proxy_http_version 1.1;
    proxy_set_header Authorization $http_authorization;
    proxy_set_header Host $host;
    proxy_buffering off;
    proxy_read_timeout 300s;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

示例只表达转发语义，实际 TLS、缓存、上传限制、跨域和安全头由部署环境统一配置。

## 8. 常见问题

| 现象 | 处理建议 |
| --- | --- |
| 安装时报 Node/pnpm 不兼容 | 使用根 `package.json` 指定的 Node 22.18/24.12 和 pnpm 11 |
| 页面仍是旧配置 | 清除站点 Local Storage/IndexedDB/缓存后重新登录 |
| 所有 API 404 | 检查 `VITE_PROXY_TARGET`、后端端口和生产 `/api` 反向代理 |
| 401 后重复提示 | 确认使用当前代码、没有多标签/自动化并发登录同一单会话账号 |
| 登录成功但侧栏为空 | 查看 `/api/iam/menus/all` 响应和菜单契约错误页 |
| 某按钮不显示 | 检查当前租户、角色及 `/api/iam/auth/codes` 权限码 |
| 页面点击后进入菜单错误 | 检查后端 `component` 语义键与 feature 公共入口是否匹配 |
| 流式聊天一次性出现 | 网关缓冲了 SSE，或中间层未按流传输 |
| 上传失败 | 检查后端 50MB 单文件/200MB 请求限制、网关限制和存储配置 |
| 构建内存不足 | 使用根构建脚本提供的 `NODE_OPTIONS=--max-old-space-size=8192`，或只构建 web-naive |
| Playwright 登录互踢 | 保持 `workers: 1`，不要并行复用同一管理员账号 |

## 9. 安全提醒

- 不要把模型 API Key、对象存储密钥、数据库密码写入任何 `VITE_*` 变量。
- 不要把本地 Store 中的权限码或角色名当作安全判断依据。
- 不要提交真实用户、租户、Token、测试密码和生产接口响应。
- 发布前检查 source map、调试日志、模板页面和演示数据。
- 管理员完成初次部署后应设置独立强密码，并限制管理端访问来源。
