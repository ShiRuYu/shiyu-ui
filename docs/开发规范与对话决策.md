# ShiYu UI 开发规范与对话决策

> 本文把 ShiYu AI 项目讨论中确认的前端产品边界、页面布局和统一交互规则固化下来。后端平台边界见 [后端开发规范与对话决策](../../shiyu-ai/docs/开发规范与对话决策.md)。

## 1. 产品与页面边界

- ShiYu UI 是 ShiYu AI 的可插拔聊天、Agent 和 RAG 工作区，不自行保存后端事实源。
- Chat 保存和展示 Conversation；Agent 工作区调用已发布 App/Agent Version；RAG 工作区展示 Knowledge/MAGMA 的授权上下文。
- Agent 平台负责定义、版本和发布；Agent 执行只允许调用 Published 版本。Draft 版本必须明确显示“不可执行”。
- Prompt Studio 管理模板、变量、版本、预览和评测，不承载意图路由配置；意图归 Agent/App 路由。

## 2. 全局 UI 规范

### 2.1 下拉菜单完整文本规则

项目统一通过 `packages/styles/src/naive/index.css` 处理 Naive UI 选择器：

1. 下拉菜单按内容伸展，避免菜单宽度被触发控件锁死。
2. 菜单最大宽度不超过视口安全范围，移动端不允许页面级横向滚动。
3. 选中值保留完整 `title`，鼠标悬浮显示完整平台、模型、App、版本、知识空间或角色名称。
4. 长选项不能只在某个页面单独修复；所有 `NSelect` 页面共享同一条规则。
5. 新增选择器时优先使用真实名称和结构化 options，不要通过缩写、手动省略号或重复 label 规避布局问题。

这条规则覆盖 Chat、Agent、App Studio、Prompt Studio、Knowledge、Education、Platform Admin 和所有表单/筛选器。

### 2.2 页面壳

| 页面类型  | 布局规则                                           |
| --------- | -------------------------------------------------- |
| Standard  | 左侧导航 224/64px，顶栏 56px，标题和主要操作同一行 |
| Immersive | Chat/学习/答题隐藏冗余导航，输入区或任务区固定可见 |
| Builder   | 资源栏 + 中央编辑区 + 右侧属性 + 底部测试/Trace    |
| Focus     | 考试、危险确认、完整 Trace 只展示当前任务必要信息  |

Chat、Agent、RAG 使用统一工作区；Context、Prompt Preview、引用、MAGMA 路径、工具审批和 Run Trace 进入同一工作流，不再维护重复的“聊天”和“调试”入口。

### 2.3 移动端和可访问性

- 768px 以下使用单栏布局；会话列表为抽屉，Context/Trace 为底部面板。
- 输入区固定在安全区域底部，首屏必须同时看见消息和输入框。
- 交互目标不小于 44px；图标按钮必须有 `aria-label`。
- 所有页面禁止横向溢出；异步请求必须处理错误、取消和 Promise rejection。
- 页面文案使用 locale；不要在页面中硬编码一套仅中文的平行标题。

## 3. 前后端联调规范

- 浏览器与后端统一使用 `/api/{domain}/**`，Vite/生产网关保留 `/api` 前缀原样转发。
- 普通请求使用 `requestClient`；流式请求使用共享 `api/stream.ts`，必须处理 `seq`、结束事件、取消、断线和服务端错误。
- 前端不拼接 Prompt；Prompt Preview 和真实运行必须使用后端同一 Context Assembly 结果。
- tenant、owner、权限和已发布版本由后端校验，前端选择器不能替代服务端授权。
- API、菜单、组件路径和权限码任一变更，都要同步更新契约测试和页面路由清单。

## 4. 页面开发流程

1. 先确认功能归属：工作台、AI 工作区、应用开发、知识中心、运行观测、教育空间、个人记录或平台管理。
2. 选择 Standard/Immersive/Builder/Focus 页面壳，不为同一业务再创建平行页面。
3. 在 `features/<domain>/api` 定义类型和请求，在 `features/<domain>/pages` 实现页面，使用 locale 和共享组件。
4. 需要新菜单时同步后端菜单语义键、权限码和角色验证。
5. 对选择器、流式输出、编辑/重试/分支、版本执行、权限错误和移动端补回归用例。
6. 完成 typecheck、单测、契约检查、构建和 E2E 后再合并。
