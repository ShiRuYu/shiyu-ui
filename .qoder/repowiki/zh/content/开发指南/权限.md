# 权限

> 官方文档：https://doc.vben.pro/guide/in-depth/access.html

框架内置三种权限控制模式：**前端访问控制**、**后端访问控制**、**混合访问控制**。

## 三种权限模式

### 1. 前端访问控制（frontend）

**原理**：在前端固定写死路由权限，通过角色遍历路由表，过滤出可访问的路由。

**适用场景**：角色较固定的系统。

**配置**：在 `preferences.ts` 中设置：

```ts
export const overridesPreferences = defineOverridesPreferences({
  app: {
    accessMode: 'frontend', // 默认值
  },
});
```

**路由权限配置**：

```ts
{
  meta: {
    // 只有 super 角色可以访问
    authority: ['super'],
  },
},
```

**确保接口返回角色匹配**（`src/store/auth.ts`）：

```ts
// userInfo.roles 必须是数组，且与路由表的 authority 匹配
// 例如：userInfo.roles = ['super', 'admin']
authStore.setUserInfo(userInfo);
```

**菜单可见但禁止访问**：

```ts
{
  meta: {
    menuVisibleWithForbidden: true, // 菜单可见，点击跳转403
  },
},
```

### 2. 后端访问控制（backend）

**原理**：通过接口动态生成路由表，前端根据数据结构生成路由并添加到实例。

**适用场景**：权限较复杂、需要动态调整的系统。

**配置**：

```ts
export const overridesPreferences = defineOverridesPreferences({
  app: {
    accessMode: 'backend',
  },
});
```

**配置菜单接口**（`src/router/access.ts`）：

```ts
async function generateAccess(options: GenerateMenuAndRoutesOptions) {
  return await generateAccessible(preferences.app.accessMode, {
    fetchMenuListAsync: async () => {
      return await getAllMenus(); // 调用后端菜单接口
    },
  });
}
```

**接口返回菜单数据格式**：

```ts
const menus = [
  {
    meta: { order: -1, title: 'Dashboard' },
    name: 'Dashboard',
    path: '/',
    redirect: '/analytics',
    children: [
      {
        name: 'Analytics',
        path: '/analytics',
        // component 为页面路径，去掉 views/ 和 .vue
        component: '/dashboard/analytics/index',
        meta: { affixTab: true, title: '分析页' },
      },
    ],
  },
];
```

### 3. 混合访问控制（mixed）

**原理**：同时结合前端固定路由权限和后端动态菜单数据，最终合并。

**适用场景**：复杂业务场景。

**配置**：

```ts
export const overridesPreferences = defineOverridesPreferences({
  app: {
    accessMode: 'mixed',
  },
});
```

需要同时满足前端路由权限配置和后端菜单接口要求。

## 按钮细粒度控制

### 权限码方式

通过接口返回权限码（字符串数组），基于权限码控制按钮显示。

**权限码获取**（`src/store/auth.ts`）：

```ts
const accessCodes = await getAccessCodes();
// 格式：['AC_100100', 'AC_100110', 'AC_100120']
accessStore.setAccessCodes(accessCodes);
```

**三种使用方式**：

```vue
<script lang="ts" setup>
import { AccessControl, useAccess } from '@vben/access';
const { hasAccessByCodes } = useAccess();
</script>

<template>
  <!-- 1. 组件方式（需指明 type="code"） -->
  <AccessControl :codes="['AC_100100']" type="code">
    <Button>仅 AC_100100 可见</Button>
  </AccessControl>

  <!-- 2. API 方式 -->
  <Button v-if="hasAccessByCodes(['AC_100100'])"> 仅 AC_100100 可见 </Button>

  <!-- 3. 指令方式 -->
  <Button v-access:code="'AC_100100'">仅 AC_100100 可见</Button>
  <Button v-access:code="['AC_100100', 'AC_100110']">多码可见</Button>
</template>
```

### 角色方式

不需要权限码，直接通过角色判断：

```vue
<script lang="ts" setup>
import { AccessControl, useAccess } from '@vben/access';
const { hasAccessByRoles } = useAccess();
</script>

<template>
  <!-- 组件方式 -->
  <AccessControl :codes="['super']">
    <Button>Super 角色可见</Button>
  </AccessControl>

  <!-- API 方式 -->
  <Button v-if="hasAccessByRoles(['super'])">Super 角色可见</Button>

  <!-- 指令方式 -->
  <Button v-access:role="'super'">Super 角色可见</Button>
  <Button v-access:role="['super', 'admin']">Super 或 Admin 可见</Button>
</template>
```

## 权限模式对比

| 模式     | 优点               | 缺点                   | 适用场景       |
| -------- | ------------------ | ---------------------- | -------------- |
| frontend | 简单，前端独立控制 | 角色改动需同步更新前端 | 角色固定的系统 |
| backend  | 灵活，后端动态管理 | 需后端提供规范数据     | 复杂权限系统   |
| mixed    | 兼顾两者           | 配置较复杂             | 复杂业务场景   |
