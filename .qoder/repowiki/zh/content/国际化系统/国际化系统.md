## 简介

本文件面向 shiyu-ui 项目的国际化系统，系统基于 Vue I18n，并通过统一的 @vben/locales 包进行封装与扩展。文档涵盖以下主题：

- Vue I18n 的集成与配置方式
- 语言包的组织结构与加载机制
- 多语言配置：语言切换、默认语言设置、语言检测
- 语言包分类：系统语言包、页面语言包、演示语言包
- 动态语言包加载与性能优化策略
- 国际化开发最佳实践：文本提取、翻译管理、本地化测试
- 新增语言支持的步骤与注意事项

## 项目结构

国际化相关代码主要分布在两个应用与一个共享包中：

- 应用层（web-naive）：负责自身语言包的加载与导出，使用 @vben/locales 完成 I18n 初始化与语言切换
- 应用层（playground）：在基础 I18n 能力之上，额外加载第三方组件库（Ant Design Vue、Day.js）的语言包
- 共享包（@vben/locales）：封装 Vue I18n 初始化、语言包映射、动态加载、缺失键告警等通用能力

### 语言包组织与命名规范

### 动态语言包加载机制

- 目录扫描与映射
  - 使用 import.meta.glob 收集所有语言包 JSON 文件
  - 通过 loadLocalesMapFromDir 将路径匹配为"语言 -> 模块名 -> 导入函数"的映射
- 动态导入与合并
  - loadLocaleMessages 会先设置当前语言，再动态导入对应语言的所有模块并合并为 messages
  - 若存在应用自定义的 loadMessages，则在合并阶段将第三方扩展消息与应用语言包合并
- 语言切换
  - setI18nLanguage 设置 i18n.global.locale 并同步 HTML lang 属性，确保 SEO 与辅助技术友好

```mermaid
flowchart TD
Start(["开始"]) --> Scan["扫描 langs 目录<br/>生成模块映射"]
Scan --> BuildMap["构建语言->模块->导入函数 映射"]
BuildMap --> LoadMsgs["loadLocaleMessages(lang)"]
LoadMsgs --> Merge["合并应用语言包"]
Merge --> ExtMerge["合并第三方扩展消息(可选)"]
ExtMerge --> SetLang["设置 i18n 语言与<html lang>"]

```

## 系统管理模块国际化支持

### 系统管理模块语言包结构

系统管理模块包含用户、菜单、角色、部门四个核心管理功能，每个功能都有完整的中英文翻译支持：

#### 用户管理（User Management）

- 基础信息：用户名、昵称、邮箱、手机号、头像
- 关联信息：所属部门、角色分配
- 状态管理：启用/禁用状态
- 操作功能：重置密码、用户列表展示

#### 菜单管理（Menu Management）

- 菜单类型：目录、菜单、按钮、内嵌、外链
- 基础属性：菜单名称、路由地址、组件路径
- 视觉配置：图标、徽章、标签页固定
- 权限控制：权限标识、激活路径
- 导航设置：面包屑隐藏、子菜单隐藏

#### 角色管理（Role Management）

- 角色信息：角色名称、角色ID
- 权限分配：角色权限设置
- 状态管理：角色启用/禁用
- 时间记录：创建时间、更新时间

#### 部门管理（Department Management）

- 组织结构：部门名称、上级部门
- 基础信息：创建时间、备注说明
- 状态管理：部门启用/禁用
- 树形结构：父子部门关系

### Vue组件中的国际化使用

#### 部门管理组件国际化

在部门管理列表组件中，国际化键值被广泛使用：

```javascript
// 使用国际化键值设置按钮文本
{{ $t('ui.actionTitle.create', [$t('system.dept.name')]) }}

// 使用国际化键值设置表格标题
<Grid table-title="部门列表">

// 在数据文件中使用国际化键值
{
  component: 'Input',
  fieldName: 'name',
  label: $t('system.dept.deptName'),
}
```

#### 菜单管理组件国际化

菜单管理组件展示了复杂的国际化使用模式：

```javascript
// 菜单类型选项的国际化

  value: 'catalog',

// 表单字段的国际化
{
  component: 'Input',

  label: $t('system.menu.menuName'),
}

// 表格列的国际化
{
  field: 'meta.title',
  title: $t('system.menu.menuTitle'),
}
```

## 通用术语国际化

### 新增术语支持

系统现已支持以下新增术语：

#### Normal（正常）

- **中文**：正常
- **英文**：Normal
- **用途**：用于状态标识、模式选择等场景
- **应用场景**：菜单徽章类型、偏好设置模式等

#### All（全部）

- **中文**：全部
- **英文**：All
- **用途**：用于筛选条件、选择器等场景
- **应用场景**：搜索过滤、数据筛选等

#### Search（搜索）

- **中文**：搜索
- **英文**：Search
- **用途**：用于搜索功能、查询按钮等场景
- **应用场景**：搜索框、查询按钮、搜索面板等

### 术语更新说明

**更新** 'Enabled' 术语已更新为 'Normal'，以保持翻译的一致性和准确性。

## 故障排查指南

- 未命中键告警
  - 若开启 missingWarn，控制台会提示未找到的键位与语言，便于定位问题
- 语言包未生效
  - 检查语言包路径与命名是否符合约定（语言目录与模块文件）
  - 确认 loadMessages 返回的消息结构正确
- 第三方库语言包未切换
  - playground 中需确认 antd 与 dayjs 的语言包已正确导入与设置
- 默认语言不生效
  - 检查 @vben/preferences 中 app.locale 的值与 SupportedLanguagesType 是否一致
- 系统管理模块翻译缺失
  - 确认 system.json 文件中包含相应的键值定义
  - 检查组件中使用的国际化键值是否正确
- 新术语未识别
  - 确认 common.json 和 preferences.json 中包含新增的 'Normal'、'All'、'Search' 术语
  - 检查术语键值拼写是否正确

## 结论

shiyu-ui 的国际化系统以 @vben/locales 为核心，实现了统一的 Vue I18n 集成、动态语言包加载与扩展能力。应用层（web-naive 与 playground）在此基础上分别按需加载自身语言包与第三方库语言包，既保证了灵活性，又维持了良好的可维护性。

**新增的系统管理模块国际化支持**进一步完善了整个国际化体系，涵盖了用户、菜单、角色、部门管理的完整中英文翻译，为系统的核心功能提供了完整的本地化支持。**新增的通用术语支持**包括 'Normal'、'All'、'Search' 等关键术语，提升了系统的用户体验一致性。

通过模块化语言包、并发加载与缺失键告警等策略，系统在易用性与性能之间取得了平衡。术语更新确保了翻译的一致性和准确性，为后续的国际化扩展奠定了坚实基础。

## 附录

### 新增语言支持步骤

- 在 apps/web-naive/src/locales/langs 下新增语言目录（如 fr-FR），并在其中创建所需的模块 JSON 文件（system.json、page.json、demos.json、common.json、preferences.json 等）
- 在 playground 对应目录下重复上述步骤
- 若需要第三方库语言包，补充对应导入与切换逻辑（参考 playground 的实现）
- 如需调整默认语言，请在 @vben/preferences 中设置 app.locale，并确保其属于 SupportedLanguagesType

### 系统管理模块国际化最佳实践

- 键值命名规范：使用 system.<模块>.<字段> 的层级结构
- 文本一致性：确保相同概念在不同模块中使用相同的翻译
- 上下文相关：根据具体使用场景选择合适的翻译
- 验证规则：表单验证错误信息也要支持国际化
- 动态内容：对于动态生成的内容，确保翻译键值正确传递
- 术语统一：遵循新增的 'Normal'、'All'、'Search' 等通用术语规范

### 术语维护指南

- **新增术语**：在 common.json 和 preferences.json 中添加对应的中英文键值对
- **术语更新**：如需更新现有术语，确保同时更新中英文版本并保持一致性
- **术语验证**：在组件中使用新术语前，先在语言包中验证键值是否存在
- **上下文检查**：确保术语在不同使用场景下的翻译准确性
